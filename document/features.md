## Feature 1 — ⚔ Dungeon Focus Lock

### Summary
When the hunter opens a Dungeon Gate, the app enters a full-screen focus mode that locks the UI to the dungeon only. The screen stays on, the app takes over the display, and the hunter cannot leave without closing the gate. Phone calls still work naturally (the OS always shows calls above any app).

### Status: ✅ Implemented

### Web APIs Used
| API | Purpose |
|---|---|
| `Fullscreen API` — `requestFullscreen()` | Hides browser chrome, app takes over entire screen |
| `Screen Wake Lock API` — `navigator.wakeLock.request('screen')` | Keeps screen on during the 25-min focus block |
| `Page Visibility API` — `visibilitychange` event | Detects if the hunter switches to another app |
| `Vibration API` — `navigator.vibrate()` | Haptic feedback on entry, block complete, and victory |

### User Flow
1. Hunter taps **▶ OPEN GATE** in the Dungeon tab
2. App requests Fullscreen → browser chrome disappears  
3. App acquires Screen Wake Lock → screen stays on
4. **Focus Lock Overlay** replaces the entire UI:
   - 🔒 Lock indicator at top
   - Boss emoji + name with red glow
   - Boss HP bar (drains with each completed block)
   - Block counter (`X / Y`)
   - Large countdown timer (turns red and pulses in the last 60 seconds)
5. **Only two actions available:**
   - `⚡ COMPLETE BLOCK` — marks the focus block done, deals damage to boss, starts next block
   - `🚪 CLOSE GATE` — retreats from dungeon, exits fullscreen, releases wake lock

### Phone Call Behaviour
> Phone calls are **always handled by the OS**, which renders the incoming call screen above any app — including fullscreen browser apps. The hunter can pick up or reject normally, then return to the dungeon.

### Cheat Detection (Page Visibility)
| Offense | Consequence |
|---|---|
| 1st tab/app switch | Orange warning banner: `⚠ FOCUS WARNING — RETURN TO THE DUNGEON, HUNTER` |
| 2nd+ switch | Red penalty banner: `⚠ FOCUS BROKEN (Nx) — THE SYSTEM HAS NOTED YOUR WEAKNESS` + logged to System Log |

### Mobile Haptics (Vibration API)
| Event | Vibration Pattern |
|---|---|
| Gate opens (focus lock enters) | `[100, 50, 100]` — double pulse |
| Block complete / boss defeated | `[300, 100, 300, 100, 500]` — victory pattern |
| Gate closed (retreat) | `[200]` — single pulse |

### Implementation Files
- [`src/components/GameApp.jsx`](../src/components/GameApp.jsx) — `enterFocusLock()`, `exitFocusLock()`, Focus Lock overlay JSX, cheat detection `useEffect`

### What Web Cannot Do (Limitations)
- ❌ Cannot block the phone home button (OS restriction)
- ❌ Cannot prevent access to other phone apps (requires native Android Kiosk mode)
- ✅ Everything else works in the browser

## Feature 2 — 📱 PWA (Progressive Web App) — Install as Phone App

### Summary
Makes the Shadow System installable on any Android or iOS device as a native-feeling app. The app gets its own home screen icon, runs in fullscreen without browser chrome, works offline with cached data, and can send push notifications for daily quest resets.

### Status: ✅ Implemented

### What PWA Unlocks
| Feature | Description |
|---|---|
| **Install on Home Screen** | Android/iOS prompt: "Add Shadow System to Home Screen" |
| **Fullscreen / Standalone mode** | No browser address bar — feels like a native app |
| **Offline support** | Quest data cached via Service Worker — works without internet |
| **Splash screen** | Branded loading screen on app launch |
| **Push Notifications** (future) | "⚔ Daily quests reset — arise, Hunter!" at midnight |
| **App icon** | Custom ⚔ icon on home screen and task switcher |

### How to Install (Android)
1. Open the app in **Chrome**
2. Tap the **⋮ menu** → "Add to Home Screen"
3. Or wait for the browser's automatic install banner
4. App appears on home screen — tap to launch in standalone fullscreen

### How to Install (iOS)
1. Open the app in **Safari**
2. Tap the **Share** button (box with arrow)
3. Tap **"Add to Home Screen"**
4. App appears on home screen — launches without Safari chrome

### Technical Details
| Component | Detail |
|---|---|
| Plugin | `vite-plugin-pwa` |
| Service Worker | Auto-generated by Workbox (cache-first strategy) |
| Manifest | `name`, `theme_color`, `background_color`, icons |
| Cache Strategy | `CacheFirst` for assets, `NetworkFirst` for Firestore |
| Icons | 192×192 and 512×512 SVG-based icons |

### Implementation Files
- [`vite.config.js`](../vite.config.js) — VitePWA plugin config, manifest, workbox options
- `public/icon-192.png` — Small app icon
- `public/icon-512.png` — Large app icon (used for splash screen)
